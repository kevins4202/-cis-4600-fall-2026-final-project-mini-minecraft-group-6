Belle Hsieh - Procedural Terrain

I implemented Perlin, FBM, and Worley noise following the lecture slides/recording using fbm(abs(Perlin)) for the jagged mountain biome and 1 - Worley for the rolling grassland hills. The two heights are blended with a LERP whose t value comes from large-grid Perlin noise passed through smoothstep(0.25, 0.75) (this is so most areas are fully one biome before transitioning). Each column is then filled with stone, dirt/grass, or stone/snow with water between y = 129 and 138. The hardest part for me was choosing noise values that made the terrain look natural. Each noise function outputs a different range so I had to measure and normalize each one before mapping it to block heights. Tuning the grid sizes took some trial and error so the terrain looked neither like static nor completely flat.

Kevin Song - Efficient Terrain Rendering and Chunking

I made Chunk inherit from Drawable so Terrain can render each chunk with one indexed draw call. I checked each filled block's six neighbors and generated only faces next to EMPTY blocks. Neighbor pointers let me check across chunk boundaries, removing hidden faces between chunks as well. I used a shared table of face corners and normals to keep face generation consistent across all six directions.

I stored each vertex's position, normal, and color consecutively in one interleaved VBO, with indices in a separate buffer. ShaderProgram::drawInterleaved reads these attributes using glVertexAttribPointer with the appropriate stride and offsets. I separated buildMeshData from bufferVBOdata, which accepts vertex and index vectors, so a background thread can generate blocks and meshes while the main thread handles input, physics, rendering, and OpenGL uploads.

For expansion, MyGL::tick calls Terrain::expandTerrain each frame. I use the player's XZ position to identify the surrounding nine zones, check hasChunkAt for missing chunks, and prioritize the smallest squared distance between a chunk's center and the player. This loads terrain ahead of the player while preserving existing chunks. My main challenges were lag when loading a bunch of new chunks, which pushed me towards the background thread solution, and keeping shared faces correct so that hidden faces don't render. I moved generation and meshing off the main thread, rebuild neighboring meshes when adding chunks, and reject background results if block revisions changed during loading so player edits are preserved.

Lucas Qu - Controllable Player Class with Simple Physics

For tick calls, I store a time delta and use this to update velocity and position independent of frames. I reset acceleration before processing inputs, apply exponential velocity damping, then integrate acceleration into velocity and velocity into displacement. For nonflight movement, I zero the Y components of the forward and right vectors and normalize them before calculating acceleration. I apply gravity separately and set upward velocity when jumping from a grounded state. For collision detection, I march rays through successive voxel boundaries and store the first intersection’s distance, block coordinates, and face normal in a struct called RayHit. I resolve X, Y, and Z movement separately by casting from points on the player’s collision volume and choosing the shortest permitted displacement. A collision clears that axis’s velocity, and a downward collision sets the "grounded" flag. Block interaction uses the same ray marcher with a three-unit ray from the camera, and placement adds the hit normal to the block coordinates and checks occupancy and overlap with the player’s bounding box. Mouse deltas are scaled into global-up yaw and local-right pitch, with pitch clamped and deltas cleared after processing.

For macOS specifically, I recenter with CGWarpMouseCursorPosition() while keeping cursor movement associated with mouse movement. This is because on some versions of Qt, the QCursor::setPos() method seems to not work as intended. I use this to keep the mouse from drifting off the screen while focused on the tab.

Milestone 2 - Multithreaded Terrain Loading (Kevin Song)

I scan the 5 x 5 generation zones around the player each tick and track completed and pending zones separately to avoid duplicate work. BlockTypeWorkers generate each missing zone's sixteen chunks, and separate VBOWorkers build meshes from snapshots of completed chunks and their neighbors. Both stages use QRunnable jobs on a bounded QThreadPool and return results through separate mutex-protected queues. The main thread connects generated chunks and uploads completed buffers, with a per-frame upload limit to keep gameplay responsive. Revision checks reject meshes made stale by edits or new neighbors, and edited chunks are also remeshed in the background.

Worker tests are in tests/terrain_workers.pro. They check zone generation, shared completion queues, boundary faces, snapshot isolation, error reporting, and shutdown.
